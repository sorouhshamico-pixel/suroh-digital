# نشر صروح الرقمية على Hostinger

## الحالة الحالية
الكود يستخدم PHP 8.2+ وMySQL مع MVC خفيف. المستودع المرتبط باسم origin هو https://github.com/sorouhshamico-pixel/suroh-digital، مع فرعي main وdevelopment. لم يُنفذ نشر على Hostinger. لا تُعد اختبارات localhost تحققًا من SSL أو DNS أو صلاحيات حساب الاستضافة.

## 1. حدود النشر والمجلد العام
الهدف هو https://digital.suroohalshami.com فقط. لا تعدل موقع الشركة الرئيسي أو مجلداته.
أنشئ مجلدًا خاصًا للمشروع خارج Document Root، ثم اضبط Document Root للدومين الفرعي على public داخل هذا المشروع. يحتوي public وحده على الملفات القابلة للوصول من المتصفح؛ app وconfig وdatabase وdocs وstorage و.env و.git تبقى خارجه.
الجذر يحتوي .htaccess يمنع الوصول عند وضع المشروع كاملًا في web root بالخطأ. لا تزل الحماية لحل خطأ 403؛ صحح Document Root.
إذا لم تسمح خطة الاستضافة بتغيير Document Root، احتفظ بالتطبيق كاملًا في مجلد خاص خارج public_html، ثم شغّل `php tools/package_hostinger.php /home/ACCOUNT/PRIVATE_APP_DIRECTORY` بالمسار الفعلي. تنتج الأداة مجلدًا جديدًا تحت storage/cache يحتوي public فقط، وindex.php يوجّه إلى public/index.php في التطبيق الخاص. لا يحتوي الحزمة على .env أو بيانات uploads. راجع المسار، ثم انسخ **محتويات** الحزمة إلى Document Root للدومين الفرعي فقط، مع الحفاظ على uploads الموجودة. لا تنشر المشروع كاملًا داخل public_html ولا تكتب فوق موقع الشركة الرئيسي. الحزمة لا تنشر شيئًا تلقائيًا.
اختُبرت rewrite وDirectoryIndex ومنع الملفات الحساسة وتنفيذ ملفات uploads محليًا على Apache 2.4؛ أعد الفحص على LiteSpeed/Apache في الاستضافة. يجب دعم .htaccess وmod_rewrite وmod_headers؛ expires اختياري للأصول.

## 2. GitHub والمراحل
المستودع المعتمد: https://github.com/sorouhshamico-pixel/suroh-digital. development للتطوير وmain للنسخة التي اجتازت CI. راجع git status وgit diff وgit check-ignore .env قبل الرفع.
لا ترفع .env أو runtime أو كلمات المرور أو بيانات الطلبات أو uploads؛ .gitignore يستثنيها.
CI يفحص PHP وJavaScript ويشغّل MySQL واختبارات HTTP ومتصفح. اختبارات قاعدة البيانات تحذف بيانات قاعدة **اختبارية فقط**؛ لا تشغلها ضد قاعدة الإنتاج.
لا تفعّل نشرًا تلقائيًا لفرع لم ينجح في CI. عنوان GitHub محدد أعلاه؛ مفتاح النشر واشتراك Hostinger يحددهما صاحب الحساب.

## 3. PHP والبيئة
فعّل PHP 8.2 أو أحدث وPDO MySQL وmbstring وDOM وsession وJSON. curl مطلوب لاختبارات التكامل.
انسخ .env.example إلى .env في المجلد الخاص، واضبط:
- APP_ENV=production
- APP_URL=https://digital.suroohalshami.com
- DB_HOST وDB_PORT وDB_DATABASE وDB_USERNAME وDB_PASSWORD بالقيم الفعلية من Hostinger.
استخدم مستخدم MySQL مخصصًا؛ لا تستخدم root. ملف .env بصلاحية 600 إذا سمحت ملكية ملفات PHP بذلك؛ لا تضعه داخل public.
لا تعتمد على ترويسات Forwarded/X-Forwarded-Proto غير الموثوقة. فعّل شهادة SSL وفرض HTTPS في hPanel أو إعداد الخادم الموثوق قبل الاختبار؛ ملفات ارتباط الإنتاج Secure.
STORAGE_PATH اختياري لمسار تخزين خاص ثابت خارج public بين إصدارات النشر. أنشئ logs وcache وsessions داخله، واجعلها قابلة للكتابة لمالك PHP فقط (700/750 بحسب مستخدم الاستضافة). ملفات الكود عادة 644 والمجلدات 755؛ لا تستخدم 777.
APP_ENV=local مخصص للتطوير؛ حينها الصفحات noindex وrobots يمنع الزحف.

## 4. قاعدة البيانات والترحيل
في تركيب جديد، أنشئ قاعدة MySQL بالاسم الفعلي، ثم استورد database/schema.sql عبر phpMyAdmin أو:
```bash
mysql -h HOST -u USER -p DATABASE < database/schema.sql
```
قبل تحديث قاعدة موجودة، خذ نسخة احتياطية من البيانات وتحقق من إمكانية استعادتها في بيئة اختبار. لا تعد استيراد schema بديلًا عن ترحيل.
```bash
mysqldump -h HOST -u USER -p --single-transaction DATABASE > /PRIVATE/BACKUPS/sorouh-before-p0.sql
php database/migrate.php --backup-confirmed
```
ترحيل P0 إضافي وقابل لإعادة التشغيل، يحافظ على البيانات وحالات CRM السابقة بما فيها lost. يضيف حقول attribution ومعرّفات الطلب والجلسة ووقت الموافقة وفهرسًا فريدًا للإرسال. لا توجد عملية حذف بيانات فيه.
MySQL DDL ليس معاملة قابلة للتراجع بالكامل. عند الفشل، احتفظ بالنسخة الاحتياطية، تحقق من الأعمدة، وأعد تشغيل الترحيل بعد معالجة السبب؛ لا تحذف الأعمدة أو الطلبات لإصلاحه.
أنشئ أول مدير باستخدام البريد الحقيقي وكلمة مرور فريدة من 12 إلى 72 بايت، عبر stdin حتى لا تظهر في سجل الأوامر:
```bash
read -r -s -p 'Admin password: ' SOROUH_ADMIN_PASSWORD
printf '\n'
printf '%s\n' "$SOROUH_ADMIN_PASSWORD" | php database/create_admin.php REAL_EMAIL --password-stdin 'مدير صروح الرقمية'
unset SOROUH_ADMIN_PASSWORD
```
السكربت يرفض استبدال حساب موجود إلا مع --reset. لا تشارك كلمات المرور في Git أو التوثيق.

## 5. إصدار آمن وتراجع
قبل أول نشر تحقق من أن Document Root ومجلد الإصدار لا يحتويان موقعًا قائمًا أو بيانات يجب الحفاظ عليها. انسخ .env وstorage/uploads إلى المسارات الخاصة المناسبة دون الكتابة فوق ملفات الإنتاج.
للتحديثات: خذ نسخة احتياطية، جهّز نسخة الإصدار منفصلة، اربط البيئة والتخزين، نفّذ الترحيل، ثم شغّل preflight. فعّل الإصدار فقط بعد نجاح الفحوص.
احتفظ بالـcommit السابق ونسخة DB وuploads. عند خلل ارجع للكود السابق؛ أعمدة P0 الإضافية متوافقة مع الكود القديم. لا تستعد نسخة DB فوق طلبات جديدة دون خطة لمصالحة البيانات.
ميزة Git في hPanel تختلف حسب الخطة. تتبع دليل Hostinger الحالي ولا تفترض أن Install Path الفارغ آمن؛ توضح وثائقهم أنه قد ينشر مباشرة في public_html. يجب أن يكون مجلد النشر النهائي متوافقًا مع public الآمن.

## 6. فحص قبل الإطلاق
شغّل من مجلد التطبيق الخاص:
```bash
php tools/preflight.php
```
يجب نجاح البيئة والدومين وامتدادات PHP وMySQL والجداول والترحيل والمدير والمجلدات الخاصة. الأداة لا تختبر DNS أو SSL أو نسخ قاعدة البيانات، ولا تتصل بمستودع GitHub.
بعدها تحقق على الدومين الحقيقي:
1. HTTP يتحول إلى HTTPS؛ الشهادة صالحة والكوكيز Secure/HttpOnly/SameSite.
2. الصفحة الرئيسية والخدمات الست والمدونة والخصوصية والشروط تعيد 200؛ الصفحة غير الموجودة 404؛ custom-solutions يتحول 301 إلى custom-software.
3. .env و.git وapp وstorage وdatabase غير قابلة للوصول، ولا توجد قوائم مجلدات أو تنفيذ PHP داخل uploads.
4. sitemap.xml يشمل الخدمات والمقالات المنشورة فقط، robots يمنع admin/api، وكل canonical وog:url يستخدم HTTPS والدومين الصحيح دون UTM.
5. الدخول والخروج ورفض الحساب غير الفعال وإدارة المقالات وتغيير حالة CRM تعمل.
6. نموذج تجريبي بموافقة صحيحة يُحفظ مرة واحدة، معه UTM ووقت الموافقة وحدث form_submit واحد؛ امسح بيانات التجربة المحددة من الإدارة/قاعدة البيانات دون حذف بيانات حقيقية.
7. جرّب رابط Haraj ورابط Mourjan ثم تنقل قبل الإرسال؛ تبقى الحملة وصفحة الدخول الصحيحتان. جرّب الهاتف وواتساب مع تعطل التتبع.
8. افحص الجوال عند 320/375/768px، لوحة الإدارة، console وسجل الأخطاء، والصور والخط والأيقونات المحلية.
9. راجع محتوى الخصوصية والشروط وحقوق الأصول بوصف الشركة وتكوين التحليلات الفعلي قبل اعتماد النصوص للنشر.
10. فعّل نسخ Hostinger اليومية لقاعدة البيانات وuploads، وجرّب الاستعادة. GitHub يحفظ الكود فقط.

## 7. التحليلات والاحتفاظ بالبيانات
التتبع الداخلي يعمل دون حساب Google. معرفات GA4/GTM فارغة افتراضيًا؛ لا تُختلق. عند تفعيل GTM يكون هو المسؤول عن إعداد الوسوم؛ لا يُحمّل GA4 المباشر معه لمنع التكرار.
قبل تفعيل وسوم إعلانية أو تتبع غير ضروري، حدّد إعدادات الموافقة وسياسة الخصوصية وراجع CSP حسب المزودين المصرح لهم. لا تضع بيانات الطلب الشخصية في dataLayer أو الأحداث.
أحداث form_submit الداخلية تُحفظ بعد نجاح المعاملة فقط. النسخة الحالية تعرض إشارة التحويل الخارجية مرة واحدة بعد redirect؛ ليست ضمان تسليم إلى Google أثناء تعطل الشبكة.
حدد مدة احتفاظ للطلبات والأحداث والسجلات واعتمدها إداريًا، ثم طبّق سياسة الحذف/الأرشفة مع النسخ الاحتياطية. لا توجد عملية حذف تلقائي لبيانات العملاء في هذه المرحلة.
محدّد المعدل الحالي يعمل على instance واحدة ويكتب ملفات خاصة. نظّف ملفات الحالة القديمة ضمن صيانة متوقفة أو نقل التخزين؛ لا تحذف حالة limiter أثناء استقبال الطلبات. التوسع لعدة instances يحتاج تخزينًا مشتركًا.
